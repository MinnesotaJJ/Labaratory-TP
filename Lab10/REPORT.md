## 3. Описание модулей и схема зависимостей

### Базовый уровень №4 — калькулятор геометрии
- `geometry.js` — вычисляет площадь и периметр прямоугольника, площадь круга и длину окружности; проверяет положительные числа.
- `ui.js` — выводит результаты и сообщения об ошибках.
- `main.js` — получает значения полей, обрабатывает события и связывает модули.

Схема: `index.html → main.js → geometry.js` и `main.js → ui.js`.

### Средний уровень №8 — список задач
- `tasks.js` — модель данных: получение, добавление, удаление и изменение статуса задачи.
- `ui.js` — отображение задач и сообщений.
- `main.js` — обработка формы и связывание модели с интерфейсом.

Схема: `index.html → main.js → tasks.js` и `main.js → ui.js`.

### Повышенный уровень №19 — Kanban
- `columns.js` — список колонок и правила перехода между ними.
- `tasks.js` — создание, перемещение, удаление и загрузка карточек.
- `storage.js` — сохранение и чтение JSON из `localStorage`.
- `ui.js` — построение карточек и кнопок.
- `main.js` — связывает все модули, обрабатывает события и синхронизирует данные.

Схема:
```text
index.html
   └── main.js
       ├── tasks.js ──→ columns.js
       ├── ui.js ─────→ columns.js
       └── storage.js
```

## 4. Использование ES-модулей

Во всех HTML-файлах точка входа подключена через:
```html
<script type="module" src="./src/main.js"></script>
```
В проектах используются именованные экспорты (`export function`, `export const`) и именованные импорты (`import { ... } from "..."`). Пути относительные. Логика вычислений и работы с данными отделена от DOM.

## 5. Обязательные требования

| Требование из методички | Реализация |
|---|---|
| Не менее 3 собственных JS-модулей (для базового допускаются 2 + main) | Базовый: 3 файла; средний: 3; повышенный: 5 |
| Не менее 2 именованных экспортов и 2 импортов | Выполнено во всех вариантах |
| Не менее 2 пользовательских событий через `addEventListener()` | Базовый: 2; средний: submit, change, click; повышенный: submit и события кнопок карточек |
| Разделение логики, DOM и данных | Реализовано отдельными модулями |
| Обработка некорректного ввода | Пустые, нулевые и отрицательные значения/названия проверяются |
| HTTP-сервер | Инструкция приведена ниже |
| Не менее 5 тестов | Для каждого варианта подготовлены автоматические проверки логики |

## 6. Тестирование

Тесты логики написаны для Node.js. Запускать из корневой папки проекта:

```bash
node --experimental-default-type=module basic/tests/geometry.test.mjs
node --experimental-default-type=module medium/tests/tasks.test.mjs
node --experimental-default-type=module advanced/tests/kanban.test.mjs
```

| Уровень | Сценарий | Входные данные | Ожидаемый результат | Проверка |
|---|---|---|---|---|
| Базовый | Прямоугольник | 5 × 3 | Площадь 15, периметр 16 | assert |
| Базовый | Круг | r = 1 | Площадь ≈ 3,14 | assert |
| Базовый | Длина окружности | r = 2 | ≈ 12,57 | assert |
| Базовый | Граничное значение | 0 | Отклонение как недопустимого | assert |
| Базовый | Некорректное значение | -2 | Отклонение | assert |
| Средний | Пустой список | нет задач | 0 задач | assert |
| Средний | Добавление | непустой текст | задача добавлена | assert |
| Средний | Пустой ввод | пробелы | ошибка валидации | assert |
| Средний | Повторное действие | переключить статус | completed = true | assert |
| Средний | Удаление | существующий ID | задача удалена | assert |
| Повышенный | Колонки | 3 колонки | список из 3 статусов | assert |
| Повышенный | Переход вперёд | todo | doing | assert |
| Повышенный | Граница перехода | todo назад | null | assert |
| Повышенный | Создание | непустое название | карточка в todo | assert |
| Повышенный | Неверный статус | wrong | переход отклонён | assert |
| Повышенный | Пустой ввод | пробелы | ошибка валидации | assert |
| Повышенный | Удаление | существующий ID | карточка удалена | assert |

**Фактический результат:** автоматические проверки логики запускаются отдельными командами; при успешном выполнении Node.js выводит сообщение о прохождении тестов. Проверку отображения в браузере необходимо выполнить по инструкции запуска и зафиксировать скриншотами.

## 7. Порядок запуска

1. Открыть папку `Lab10_ESModules` в VS Code.
2. Открыть терминал в корневой папке проекта.
3. Выполнить:
   ```bash
   python -m http.server 8000
   ```
4. Открыть в браузере `http://localhost:8000`.
5. Выбрать нужный уровень и проверить приложение.
6. Для проверки модулей открыть DevTools → Console и Network. Ошибок загрузки модулей быть не должно.
7. Запустить три команды тестирования из раздела 6.

Не открывать HTML напрямую через `file://`, так как ES-модули рекомендуется запускать через HTTP-сервер.

## 8. Дополнительное творческое задание

В повышенном варианте добавлен независимый `storage.js`, который сохраняет карточки в `localStorage` в формате JSON. При повторном открытии страницы карточки восстанавливаются. Разделение хранения от бизнес-логики позволяет заменить способ хранения без переписывания интерфейса и правил Kanban.
